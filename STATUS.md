## What is decided (normative, in DESIGN.md and GRAMMAR.md)

- Sixteen codes: SOH STX ETX EOT ENQ BEL DLE SYN ETB CAN EM SUB FS GS RS US.
  HT LF CR SP are layout outside text.
- Text is `STX … ETX`; seven codes are escaped inside it with a DLE
  prefix (STX ETX DLE ETB EOT SYN EM). Everything else is raw.
- Nesting is `DLE <opener> … CAN`.
- Keyed records `RS SOH k US v …`. Key order is data and is preserved;
  canonical form requires only unique keys (duplicate: last wins, warning).
- Header row `SOH RS name US name …`.
- BEL + content is a note; bare BEL before FS/GS/RS/SOH/DLE marks the
  element dead.
- SYN heading (shape, version, blob) … body … EOT. Missing SYN is a loud
  warning. EM begins a raw blob region declared in the first heading.
- ETB commits a stream block.
- References `ENQ name` (a group) or `ENQ DLE … CAN`, a **pattern**: a
  level that is the target with its values left out (`␅␐␝tags␞001␟label␘`;
  file line, GS depth, `␞␁host␟` for a keyed unit, a level in the third
  unit to continue into a field's level). Decided 2026-11-10; replaces the
  US-separated text path, which is now an error. Resolution is
  **nearest wins**: the closest matching target before the ENQ, else the
  first after; stream readers resolve against committed blocks only.
  Hashed as written.
- **SUB is subordinate** (decided 2026-11-14/15, written c0-spec `ccf5ae3`
  and `6da01b0`): SUB before a code makes the element after it a child of
  the element before, at that code's grain. Open in 1.0: **SUB GS, a
  subsection** (`group-line = [ BEL L ] *( SUB L ) GS L name L`, depth one
  plus the SUB count) and **SUB US, a sub-unit** (`unit = [ value L ] *note
  *sub-unit`, `sub-unit = 1*( SUB L ) US L [ value L ] *note`; not a unit of
  the record; keyed values take them too; the heading's values do not).
  Reserved, errors: SUB RS (sub-record), SUB FS, SUB SOH. Rules at every
  grain: layout may follow SUB; a skip is an error measured against the
  element before at that grain as written, dead or not; first group of a
  file at depth one, FS restarts; `␇␚␝b` dead, `␚␇␝b` and `␇␚␟` errors;
  the prefix is structure, kept in canonical form. Repetition is an empty
  element for every code, GS included (`␝␝b` = empty group then `b`; no
  limitation, no canonicaliser refusal). **Supersession is withdrawn** as
  a meaning; its unit-grain bytes survive as the sub-unit, so **C0DIFF**
  (`DIFF.md`) is unchanged in bytes: anchored patterns, `old␚␟new` the
  sub-unit of `old`, every unused slot an error, no replace-all mark,
  uniqueness to end of file, no diff grammar. MARK.md's bytes stand too.
- Heading keys `shape` (`diff` | `stream`), `version`, `blob`, and
  `schema` (a name, or a keyed record of `name`, `url`, `hash`, the hash
  of the schema's canonical body; decided 2026-11-11, the shape hints cut
  the same day).
- Canonical form: no layout, notes, dead elements or framing; one spelling
  per value; unique keys. Canonical spans (record, group, body) are
  hashing helpers only; ordering is the producer's job.

## Library API decisions (not spec, but shared by all ports)

- Every Builder has one primitive per code: `fs gs rs us sub soh dle can
  bel enq syn eot etb em`, each writing its code plus an optional
  follower, sharing record state with the composed methods (`group`,
  `header`, `record`, `field`, `map`, `key`, `level`, `list`, `ref`,
  `note`), all returning the builder. No `stx`/`etx` primitive: value
  spelling is automatic so output stays canonical. Bare `sub` writes
  SUB before the next primitive (supersession); the pair convenience
  `us("10").sub("20")` is withdrawn with the pair (2026-11-10). Rust and C spell the optional form as a suffix pair
  (`rs()`/`rs_value(v)`); Go uses variadics.
- Go and Rust have no hash-taking `map`/`syn`; use `key`/`heading`
  chains, because their maps are unordered and key order is data.
- **Parse is validate (decided 2026-11-13).** Constructing a document or
  body from bytes applies the whole grammar to every unit and level and
  fails on malformed input: there is no model for a record the grammar
  rejects, and the stream reader finds a damaged block by the parser
  failing inside it. Canonical checking is opt-in (a validator entry
  point or flag) and never fails construction; it reports violations.
  Two severities, as DESIGN.md says. Before Crystal `ed4db5a` the model
  only indexed structure and let malformed units through to the
  accessors; that leniency is gone in every port.

1. **C0DIFF and format reviews: decided, written and ported.** Two
   independent reviews were run 2026-11-09
   (`notes/REVIEW-2026-11-09-C0DIFF.md`, `-FORMAT.md`) and their
   decisions taken in order, 2026-11-08 to 2026-11-12, all by the author;
   the history is in `notes/PROPOSAL-SUPERSESSION.md` and
   `notes/PROPOSAL-SUB-DEPTH.md`. What they settled, now normative:
   one mechanism in the base grammar and two specifications, C0DIFF
   (`DIFF.md`, gates 1.0) and C0MARK (`MARK.md`, preliminary, 1.x); the
   mechanism is SUB before a separator, first read as supersession
   (2026-11-10) and then as subordination (item 0); the diff is a body
   under constraints and every unused slot is an error, dead records and
   dead file lines included (a hunk that reads as live but does not apply
   is a hazard; a hunk is kept in a text note `␇␂␞…␃`); a record with no
   substitution is an assertion; no replace-all mark, ever (a tool expands
   one against the target; the inverse diff is undo); uniqueness measured
   to end of file; a SUB prefix is structure, hashed as written; dead
   means the element and everything it holds; a header row anywhere but
   first is an error; references are `ENQ DLE … CAN` patterns, nearest
   wins, the text path form an error; a header row names its own group's
   fields, subsections inherit nothing; the `shape` hints are cut
   (`diff` | `stream`) and a `schema` heading key added (a name, or a
   level holding one keyed record of `name`, `url`, `hash`); any error
   inside a committed block damages the block, the reader stops there by
   default with a resume offset and continues only when asked; the
   terminology pass (canonical span, severity, depth, value, record id,
   framing); a header row admits notes; duplicate heading key last wins
   with a loud warning; STX/US after a payload damages the block; SYN
   mid-stream tears as a torn tail; keyed blob rows legal. **Ported
   2026-11-12/13 in all seven** (c0-spec `7b13feb`, 277 vectors), then
   superseded by item 0's round. Settled while porting: a body whose
   every element is dead is an empty body and reports one empty leading
   file (`␇␜b␞2`); a damaged stream block contributes nothing to the parse
   state; a diff tool refuses a second document after the diff's EOT.

## How to resume

1. Read DESIGN.md, then GRAMMAR.md, then DIFF.md; `notes/` is history.
2. Everything is pushed and every port is on `f677533`. A spec change
   goes: decide, write DESIGN/GRAMMAR, regenerate vectors with
   `vectors/gen.py`, commit here, then Crystal (`c0-cr/src/c0/parser.cr`
   is the reference walk), then JS, Rust, Go, C, then Python and Ruby over
   the C core, each against the vectors; never hand-edit a vector. c0-fmt
   follows c0-cr (it depends on `main`).
3. Settle item 1a, bump to 1.0.0, tag `v1.0.0` everywhere, publish,
   update downstream.

## Working conventions that were in force

- Discuss and decide each design question before any code. State churn up
  front. Show concrete bytes. Compatibility was not a constraint before
  1.0; after 1.0 it is.
- Branch per port for large changes, fast-forward merge, delete the branch.
- Crystal is the reference; when a port finds a reference bug, fix Crystal
  and add a vector so every port shares the fix.
