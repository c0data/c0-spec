## What is decided (normative, in DESIGN.md and GRAMMAR.md)

- Sixteen codes: SOH STX ETX EOT ENQ BEL DLE SYN ETB CAN EM SUB FS GS RS US.
  HT LF CR SP are layout outside text.
- Text is `STX … ETX`; seven codes are escaped inside it with a DLE
  prefix (STX ETX DLE ETB EOT SYN EM). Everything else is raw.
- Nesting is `DLE <opener> … CAN`.
- Keyed records `RS SOH k US v …`. Key order is data and is preserved;
  canonical form requires only unique keys (duplicate: last wins, warning).
- Header row `SOH RS name US name …`.
- BEL + content is a note; bare BEL before FS/GS/RS/SOH/DLE marks the
  element dead.
- SYN heading (shape, version, blob) … body … EOT. Missing SYN is a loud
  warning. EM begins a raw blob region declared in the first heading.
- ETB commits a stream block.
- References `ENQ name` or `ENQ STX a US b [US c] ETX`, every segment a
  name, resolved in any order against the whole body; stream readers
  resolve against committed blocks only. Hashed as written.
- Canonical form: no layout, notes, dead elements or framing; one spelling
  per value; unique keys. Canonical units (record, group, body) are
  hashing helpers only; ordering is the producer's job.

## Library API decisions (not spec, but shared by all ports)

- Every Builder has one primitive per code: `fs gs rs us sub soh dle can
  bel enq syn eot etb em`, each writing its code plus an optional
  follower, sharing record state with the composed methods (`group`,
  `header`, `record`, `field`, `map`, `key`, `level`, `list`, `ref`,
  `note`), all returning the builder. No `stx`/`etx` primitive: value
  spelling is automatic so output stays canonical. `sub` is for C0-DIFF
  only. Rust and C spell the optional form as a suffix pair
  (`rs()`/`rs_value(v)`); Go uses variadics.
- Go and Rust have no hash-taking `map`/`syn`; use `key`/`heading`
  chains, because their maps are unordered and key order is data.

## What is open

1. **C0DIFF review.** The author wants to review the diff as a whole before
   1.0 is tagged. It currently uses a second grammar (`diff-body`) with the
   pattern on the GS line, which fails the framework rule that every shape
   parses under the base grammar. The direction worked out (2026-11-07) is
   in `notes/SKETCH-SUBSTITUTION.md`: the pair `old␚new` becomes a unit
   kind of the base grammar, and a diff is files of records whose plain
   units are anchors and whose pairs are substitutions; the semantics of
   DIFF.md carry over unchanged. Two separate proposals ride alongside and
   do not gate 1.0: islands (a level inside text) for editor markup, and
   supersession (`SUB` before FS/GS/RS replaces the previous sibling) for
   data and logs. **Undecided:** the pair as grammar (yes/no), replace-all
   (constraints stated, no mark), where uniqueness is measured, GS in a
   diff. Affects DIFF.md, GRAMMAR.md, 32 diff vectors, and the diff
   modules of Crystal, JS, Rust, Go and C. The name drops its hyphen:
   C0DIFF.
2. **Tags and releases.** Tag `v1.0.0` across all repos after the C0-DIFF
   review. Registry names: `c0` is taken on npm; `c0data` is free on npm,
   crates.io, PyPI and RubyGems. Recommendation on record: publish as
   `c0data` everywhere. No publish workflows exist yet (CI only tests).
3. **Cosmetic, Crystal Pretty:** continues a record on the line of a
   closing `␘`; groups are not indented under `␜` as the DESIGN example
   shows.
4. **Downstream:** keep/finfry and transfs still consume 0.x; move them
   to 1.0 after tagging.
5. Landing page benchmarks to re-run on 1.0. Editor extension to install
   and try. A blog post on the ASCII-era message format was wanted.

## How to resume

1. Read DESIGN.md, then GRAMMAR.md, then DIFF.md, then
   `notes/SKETCH-SUBSTITUTION.md`.
2. Decide the C0DIFF questions above, constraints first.
3. Update DIFF.md and GRAMMAR.md; regenerate vectors with `vectors/gen.py`;
   port Crystal first (it is the reference), then the others, each
   against the vectors; never hand-edit a vector.
4. Tag `v1.0.0` everywhere, publish, update downstream.

## Working conventions that were in force

- Discuss and decide each design question before any code. State churn up
  front. Show concrete bytes. Compatibility was not a constraint before
  1.0; after 1.0 it is.
- Branch per port for large changes, fast-forward merge, delete the branch.
- Crystal is the reference; when a port finds a reference bug, fix Crystal
  and add a vector so every port shares the fix.
